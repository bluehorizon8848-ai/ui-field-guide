# 10 · 做了个能用的东西：63 个 UI Pattern，全部可交互

> 首发第 10 篇 · 产品发布

## 为什么做这个

我是用 AI 写代码的独立开发者。

这两年我积累的最大瓶颈不是技术，是**词不对**。我知道我想要一个「从下面弹出来能选的东西」，但搜不到、说不清、告诉 AI 也不准。

试过各种方案：
- 搜设计文档 → 术语准确但默认你已经有设计能力
- 翻组件库文档 → 讲 API 不讲什么时候不该用
- 截图存灵感文件夹 → 三年后再看还是认不出来

于是我想：**做一个专门解决「知道要什么但不知道叫什么」的词典。**

## 做了什么

**63 个 UI Pattern**，不是列表，是每个都能点、能玩。

从 Accordion 到 Toast，从 Skeleton 到 Bottom Sheet。每个词条的第一个元素是 Demo，不是定义。

还有：
- **8 组对比** —— Toast vs Snackbar vs Alert 这类「它们到底什么区别」
- **中文口语搜索** —— 搜「底下弹出来」「转圈圈」能搜到
- **我不知道它叫什么** —— 回答两个问题，列出候选
- **三层 Ask AI Prompt** —— 从你平时怎么说话，到实现级描述
- **Bad → Better Prompt** —— 同一需求怎么问才有好结果
- **分享卡片** —— 3:4 和 1:1，浏览器直接导出 PNG

## 三个我坚持的原则

### 1. Example First

先看和玩，再理解定义。

理由：独立开发者的判断力是「见过的次数」，不是「读过的字数」。

### 2. Plain Language First

```
❌ Toast 是一种轻量级的非模态瞬时反馈机制。
✅ 发完消息后屏幕角落飘出来的「已发送」，几秒自己消失。
   —— 这个叫 Toast。
```

### 3. AI Translation

这是我和所有词典最根本的区别。

**每个词条最后一块永远是「怎么准确告诉 AI」。**

因为对我们来说，知道了名字之后，下一步不是去实现，是**让 AI 实现**。

## 有个功能我本来想做 AI 版，后来没做

「我不知道它叫什么」这个工具，最自然的做法是接个 AI：你描述一下，我告诉你这是什么。

我没做。改成了两个固定问题（出现在哪儿 / 主要干什么）+ 本地规则匹配。

原因：**AI 会给你编一个不存在的词条名。** 我测过，它真的会说出「Popover Sheet」这种东西 —— 听着特别合理，但搜不到。

规则匹配不会编。每个候选都是词典里真实存在的，点进去就有完整解释。而且瞬间出结果，零 API 成本。

**这不是技术能力问题，是产品取向问题。** 一个会编答案的词典，比一个不会的词典更糟。

## 技术上

Next.js 15 + React 19 + Tailwind，纯静态。

**没有账号，没有数据库，没有后端，没有 AI API。**

学习进度存 LocalStorage，分享卡片用 Canvas 在浏览器本地生成 —— 图片不上传。

部署到 Cloudflare Pages，构建产物 83 个静态页面。

## 隐私

没有埋点、没有分析脚本、没有第三方字体。

你的浏览记录只有你自己看得见。清除浏览器数据 = 清空全部状态。
