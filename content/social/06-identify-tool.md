# 06 · 我把「不知道它叫什么」变成了一个筛选器

> 首发第 6 篇 · 引入 Identify 工具

## 痛点

你打开一个 App，看到一个组件：**很帅，但你不认识**。

以前的路径：截图 → 存进「灵感」文件夹 → 永远不会再打开。

真正需要的是**当场把它翻译成术语**。因为只有知道名字，你才能：搜到资料、告诉 AI、在设计稿上标注、和别人讨论。

## 为什么「搜描述」不够

试过在 Google 搜「那个从下面弹出来的」，搜出来的是营销文章，不是组件名。

因为**搜索是基于词的，而你的记忆是基于画面的**。

## 换一种问法

别问「它叫什么」，问两个具体的：

### 第一问：它出现在哪儿

这是最容易回答的，因为答案就在你眼前。

| 你看到的 | 对应 |
| --- | --- |
| 贴着屏幕下边缘 | bottom |
| 从左边/右边滑出 | side |
| 内容区正中间 | center |
| 跟着某个元素飘 | floating |
| 盖住整页、背后变暗 | overlay |
| 就在正文里，不浮 | inline |

### 第二问：它主要在干嘛

| 它做的事 | 对应 |
| --- | --- |
| 换页面、换层级 | navigate |
| 从几个里挑一个 | select |
| 打字、选日期 | input |
| 纯告知，不要求操作 | inform |
| 展开/收起一段 | expand |
| 加载中 / 成功 / 失败 | status |
| 提交、新建、开始 | create |
| 要用户点头 | confirm |

### 交叉之后

| 在哪 | 做什么 | 候选 |
| --- | --- | --- |
| bottom | select | Bottom Sheet、Drawer |
| side | navigate | Drawer、Navigation Rail |
| center | confirm | Modal、Alert |
| floating | inform | Tooltip、Popover |
| inline | expand | Accordion、Collapsible |

**两个答案，通常就锁定 2-4 个候选。** 每个都带示意图，扫一眼就知道是哪个。

## 为什么不直接问 AI

试过。AI 会给你「您可能想要的是 Bottom Sheet 或 Action Sheet」——听起来很合理，但它可能编一个不存在的词给你。

**规则匹配不会编。** 每个候选都是词典里真实存在的词条，点进去就有完整解释。

而且本地规则是**瞬间**的，没有网络请求，没有 API 成本，没有延迟。

## 顺手一个副产品

用了两周之后，我发现一件事：回答「它主要在干嘛」这个问题，本身就在训练我的设计判断。

因为「这个组件到底在干什么」——这是设计里最难说清的事。工具帮你练习。

---

**一句话记住：** 说不清叫什么，就回答「在哪」和「干什么」。
