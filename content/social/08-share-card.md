# 08 · 分享卡片：我不想让 AI 帮我写 Prompt，我想让 AI 帮我抄

> 首发第 8 篇 · 引入 Share Card 与产品自传播

## 痛点

学了一个 UI 术语，转头就忘。想记下来，只能截图。

截图的问题：**没有名字**。三个月后再看到，还是认不出来。

## 卡片里放什么

我想了很久，最后定了 5 块：

```
┌─────────────────────────┐
│ 弹层 · CONTAINERS       │  ← 分类，方便归档
│                         │
│ Bottom Sheet            │  ← 英文名
│ 底部面板                 │  ← 中文名
│                         │
│ 贴着屏幕底部升起，       │  ← 一句话人话
│ 承载一组选择。           │
│                         │
│ ┌─────────────────────┐ │
│ │  ▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁  │ │  ← 示意图
│ │  ▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔  │ │
│ └─────────────────────┘ │
│                         │
│ 适合：筛选、多选         │  ← 什么时候用
│                         │
│ Ask AI                   │
│ 「用 Bottom Sheet 做…」  │  ← 怎么告诉 AI
│                         │
│ UI Field Guide          │
└─────────────────────────┘
```

**最下那块 Ask AI 是关键。** 前面都是知识，最后那块是行动 —— 知道名字之后，下一步是去让 AI 做出来。

## 为什么是 3:4 和 1:1

小红书 / Instagram 竖版 3:4，朋友圈方图 1:1。**只做竖版等于放弃一半渠道。**

一次生成两个尺寸，切换预览，点下载。不折腾。

## 技术上完全不需要后端

一开始我想做「上传卡片到 CDN 生成短链」，后来发现没必要：

1. 卡片内容全在本地数据里
2. Canvas 2D 直接画
3. `canvas.toBlob()` 导出 PNG

**没有图片上传，没有服务器，没有存储成本。** 隐私上也干净：卡片不出你的浏览器。

需要注意的是中文字体。Canvas 绘制中文时如果 `font` 写错会渲染成方块，所以要把系统中文字体明确写进 `ctx.font`。

## 一个反直觉的点

分享卡片是**唯一会让人主动传播这个产品的东西**。

词条页做得再好，是「我要学的时候来看」。卡片是「我看到一个好东西，顺手发给同事」。

所以它的设计目标不是「信息完整」，是**在信息流里 0.5 秒能看懂**。这就是为什么示意图必须大、为什么只有一句话、为什么不做成海报。

## 我做的取舍

| 想要 | 实际 | 为什么 |
| --- | --- | --- |
| 品牌 logo、配色、二维码 | 全砍 | 卡片不是广告，是工具 |
| 一堆标签、相关词 | 砍 | 缩略图尺寸下看不清 |
| 可自定义主题色 | 没做 | 增加复杂度，没人用 |
