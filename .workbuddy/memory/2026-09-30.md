## 静态导出 + Git 初始化

### 1. 开启 output: 'export'

`next.config.js` 改动：

```js
output: 'export',
images: { unoptimized: true },   // 原本就有，是 export 前置条件
trailingSlash: true,             // 新增，产出 patterns/modal/index.html 形式
```

`trailingSlash: true` 是为纯静态托管准备的：Cloudflare Pages 和 Nginx 都能直接命中目录形式，不需要 URL 重写规则。

**踩坑：Route Handler 必须显式声明静态。** 首次构建报错：

```
Error: export const dynamic = "force-static"/export const revalidate not configured
on route "/robots.txt" with "output: export".
```

修法：`src/app/robots.ts` 和 `src/app/sitemap.ts` 各加一行 `export const dynamic = 'force-static';`。

导出产物：187 文件 / 7.6 MB。

### 2. 本地静态预览服务器

`output: 'export'` 后 `next start` 直接失效，新增 `scripts/serve-export.mjs` + `npm run serve`。

**为什么不用 `python -m http.server`：**

| 行为 | python http.server | serve-export.mjs | Cloudflare Pages |
| --- | --- | --- | --- |
| 目录补尾斜杠 | 301 ✓ | 301 ✓ | 301 ✓ |
| 404 回退 404.html | ✗ 返回 Python 错误页 | ✓ 保留 404 状态码 | ✓ |

第一次用 Python 服务器跑，78 页里只有 404 页失败——因为它返回 500 字节英文错误页，被判成「body 几乎为空」。这是服务器问题不是产物问题（`out/404.html` 有 28 KB 完整内容）。

**中间踩的更隐蔽的坑**：先写了个内联 Python 404 handler，想给无尾斜杠路径补 301，结果判断条件写错，把 `/patterns/modal` 这类正常路径也判成不存在并返回 `404.html`（HTTP 200），78 页全挂。教训是**改 `SimpleHTTPRequestHandler` 行为时很容易破坏原生重定向**，最后老老实实写成独立 Node 脚本，显式处理 301 / 200 / 404 三种情况。

serve-export.mjs 还做了防目录穿越（`target.startsWith(ROOT)`）和缓存头区分（HTML no-cache / 资源 immutable）。
