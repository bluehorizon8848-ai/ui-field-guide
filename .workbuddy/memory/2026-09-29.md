## UI Field Guide — 0 到 1 交付完成

空目录起项目，做完可运行/可浏览/可部署的 Web 产品。定位：AI 独立开发者的 UI/UX 可视化词典。

**最终规模**：63 个 Pattern / 63 个可交互 Demo / 8 组 Comparison / 83 个静态页面。
**技术栈**：Next.js 15 App Router + React 19 + Tailwind 3.4 + lucide-react，零后端零 API。

### 关键工程决策

1. **Identify 工具改成数据驱动**
   原本维护手工矩阵 `identifyMatrix`（位置×作用→候选 id），和 Pattern 自己的字段是两套真相。
   改为在 `UIPattern` 上新增 `position: Position[]` 维度，`job` 直接复用原字段，
   `identifyCandidates()` 从 `patterns` 数组现场过滤。加新词条自动覆盖，不用改两处。

2. **Appearance vs Position 必须分开**
   Appearance 讲「怎么出现」（always/on-click/on-hover/on-scroll/auto），
   Position 讲「在哪」（top/bottom/center/floating/overlay/side/inline）。
   最初把两者混为一谈，导致 Identify 规则无法从数据推导。

3. **Server/Client 边界踩坑**
   `registry.ts` 标了 `'use client'`，Server Component 不能 import 它的对象做查表，
   预渲染会报 `Attempted to call hasDemo() from the server but hasDemo is on the client`。
   解法拆两处：
   - `src/data/demoIds.ts` — 纯数据 `hasDemo()`，供 Server Component 用
   - `src/components/demo/DemoById.tsx` — Client 组件，内部查 registry
   - `registry.ts` 顶部加 dev 断言校验两者一致

4. **硬编码 id 全部换 useId**
   Dialog/BottomSheet/TextField/TextArea/Slider/Select/InlineValidation 的
   `id` / `aria-labelledby` / `htmlFor` 都是硬编码，同页面出现两个实例就会撞。
   统一改 `useId()` 生成。

5. **Dialog 焦点归还失效**
   `triggerRef` 声明了但从未 `ref={triggerRef}` 挂到按钮上，
   `triggerRef.current` 恒为 null，关闭后焦点掉到 BODY。
   BottomSheet / Drawer 都挂对了，只有 Dialog 漏了。

### 环境坑（重要，会重复踩）

**WorkBuddy 注入的 `NODE_OPTIONS` FS shim 会让 Next 构建失败。**
症状：`EEXIST: file already exists, mkdir '.next/server'`。
解法：`env -u NODE_OPTIONS -u CODEBUDDY_BROKERED_FS_HOOK_ENABLED npm run build`。

**localhost 请求被 HTTP_PROXY 拦截返回 502。**
WorkBuddy 设了 `HTTP_PROXY=http://127.0.0.1:64042`，连 localhost 也走代理。
解法：`export no_proxy="*"; unset http_proxy https_proxy HTTP_PROXY HTTPS_PROXY`。

**后台 server 进程会随父 shell 退出被杀。**
`nohup ... & disown` 无效。解法：用 Bash 工具的 `run_in_background: true` 托管长驻进程。

**真实路径是 `Workbuddy`（小写 b），不是 `WorkBuddy`。**
`pwd -P` 显示 `/Users/bluehorizon/WorkBuddy/UI-Study` 实际解析到 `Workbuddy`，
早期构建缓存报错与此有关。

### 触控热区最后一轮修复

初次跑 `visual.mjs` 报 6 处不达标，逐一定位后修复：

| 文件 | 问题 | 修法 |
| --- | --- | --- |
| `src/components/home/InteractiveStrip.tsx` | 主 CTA 36px、次级文字链接 20px | 加 `inline-flex min-h-[44px] items-center` |
| `src/components/layout/Footer.tsx` | 三组列表链接均 16px | 全部改 `inline-flex min-h-[44px] items-center` |
| `src/components/patterns/MarkLearnedButton.tsx` | 34px | 加 `min-h-[44px]` |
| `src/components/patterns/PatternDetailClient.tsx` | 分享按钮 34px、面包屑链接、章节 CTA | 同上加 `min-h-[44px]` |
| `src/components/ui/CopyButton.tsx` | 30px | 加 `min-h-[44px]` |
| `src/components/patterns/AskAI.tsx` | 三层 Tab 按钮 | 加 `min-h-[44px]` |
| `src/components/demo/InputDemos.tsx` | Switch 视觉轨道只有 26px 高 | **视觉与热区分离**：button 撑 44×44 grid 居中，内部 span 保持 26×44 视觉轨道 |

Switch 那处是关键教训：**Toggle 类组件的视觉尺寸可以小于热区**，不能直接给轨道加 padding。正确做法是外层 button 提供 44×44 命中区，内部 span 只负责视觉。
